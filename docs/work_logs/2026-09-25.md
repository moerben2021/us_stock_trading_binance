## 项目：美股定投框架

### 今日完成

#### 1. 需求讨论和澄清（03:31 - 约04:00）

通过 brainstorming 技能与用户进行了详细的需求讨论：

**核心需求确认：**
- 基于 Binance 美股交易 API 的定投框架
- 支持多账户、多策略实例
- 三种策略：DCA、Drawdown、价值平均
- 支持买入和卖出（自动触发 + 手动干预）
- 企业微信通知（即时 + 定时汇总）
- SQLite 本地记录所有操作
- 配置文件管理，敏感信息分离

**关键决策：**
1. **策略类型**：最终确定为 DCA、Drawdown、纯粹价值平均三种
   - 价值平均策略：该买就买、该卖就卖（用户最终决策）
   - 放弃了最初的"修改版价值平均"（避免逻辑重叠）

2. **执行方式**：
   - 不同策略可配置不同执行频率
   - Python 常驻进程，通过 PM2 管理

3. **数据源**：
   - 历史行情：yFinance（考虑除权除息）
   - 实时价格：Binance API

4. **配置管理**：
   - 分层配置：业务配置和敏感信息分离
   - 配置文件是唯一配置源
   - 数据库只存执行记录

5. **卖出规则**：
   - DCA 和 Drawdown 支持配置通用卖出规则
   - 价值平均策略不支持额外卖出规则（卖出是其核心逻辑）

6. **其他重要决策**：
   - 手动交易通过配置文件触发
   - 日志按日期轮转，手动删除
   - 每次交易后 + 定时汇总通知
   - 余额不足可配置：部分执行/全部跳过

**问题讨论记录：**
- 共提出 15 个澄清问题
- 所有核心功能需求已明确
- 边界情况和异常处理策略已确定

#### 2. 架构设计（约04:00 - 04:30）

**总体架构：**
- 采用分层模块架构（方案 A）
- 职责清晰：核心业务层、策略层、集成层、存储层、配置层

**核心模块设计：**
- **Scheduler**：管理所有定时任务，智能调度
- **Strategy Engine**：协调策略执行，持仓同步，数据获取
- **Trade Executor**：交易执行，重试机制，余额检查
- **Account Manager**：账户管理，快照维护

**策略设计：**
- 策略基类定义统一接口
- `calculate()` 方法返回交易信号
- `get_required_data()` 声明数据需求

**数据设计：**
- 5 张数据库表：trades, strategy_executions, positions, account_snapshots, notifications
- 配置文件 + SQLite 的职责划分
- strategy_executions 包含配置快照（可追溯）

**关键问题解决：**
1. ✅ 卖出规则冲突 → 价值平均策略不配置通用卖出规则
2. ✅ 持仓同步机制 → 策略执行前同步 Binance 实际持仓
3. ✅ 智能调度 → 只在需要执行的日期触发
4. ✅ 手动交易并发安全 → 文件锁和重命名机制
5. ✅ API 限流处理 → 限流检测 + 429 响应处理
6. ✅ 余额不足处理 → 可配置策略（partial/skip）
7. ✅ 卖出语义明确 → 定义 sell_type 类型
8. ✅ 时区处理 → UTC 存储 + 美东时间计算
9. ✅ 异常恢复机制 → 启动时状态检查

### 技术决策记录

1. **架构选择：分层模块架构**
   - 理由：职责清晰，适度复杂，易于维护
   - 替代方案：事件驱动架构、插件化架构

2. **配置 vs 数据库：配置文件为源**
   - 理由：单一数据源，避免不一致
   - 配置追溯：strategy_executions 包含配置快照

3. **持仓同步：策略执行前同步**
   - 理由：避免外部交易导致的数据不一致
   - 实现：以 Binance API 数据为准

4. **智能调度 vs 每天触发**
   - 选择：智能调度
   - 理由：减少无效执行，降低系统负载
