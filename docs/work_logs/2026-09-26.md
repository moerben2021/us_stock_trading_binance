### 1. ✅ Binance 股票交易 API 签名验证失败（-1022 错误）

**问题根源**：
- 通过对比用户之前成功的 `tqqq-bot` 项目代码，发现签名生成方式不正确
- 原实现使用手动拼接：`"&".join([f"{k}={v}" for k, v in sorted(params.items())])`
- 正确方式应该使用：`urllib.parse.urlencode(params)`

**关键差异**：
- `urlencode()` 会自动进行 URL 编码（百分号编码）
- 手动拼接不会处理特殊字符，导致签名不匹配

**修复内容**：
1. 在 `integrations/binance_client.py` 添加 `from urllib.parse import urlencode` 导入
2. 修改 `_generate_signature()` 方法：
   ```python
   # 修改前
   query_string = "&".join([f"{k}={v}" for k, v in sorted(params.items())])
   
   # 修改后
   query_string = urlencode(params)
   ```

**验证结果**：
- ✅ 资金账户查询成功
- ✅ 下单接口返回订单ID（status: "S"）
- ✅ 签名验证通过

**参考代码位置**：
- 成功案例：`E:\ws\wb\finacial\qqqvssmh\tqqq-bot\src\broker\transport.py:135-136`
- 修复文件：`integrations/binance_client.py:262-263`

### 2. ✅ 被 0 除错误（float division by zero）

**问题根源**：
- 周末市场关闭时，订单被接受但未成交（`executedQty=0`）
- 代码仍然继续执行持仓更新逻辑
- 在计算平均成本时：`new_cost = (old_qty * old_cost + quantity * price) / new_qty`
- 当 `quantity=0` 且 `old_qty=0` 时，`new_qty=0`，导致除以零错误

**问题发生位置**：
- `core/trade_executor.py:287` - `_update_position()` 方法

**修复方案**（两层防护）：

**第一层：下单后查询订单详情**
- 添加 `ENDPOINT_ORDER_DETAIL = "/sapi/v1/equity/order/detail"`
- 添加 `get_order_detail(order_id)` 方法
- 在 `_execute_buy()` 中下单后立即查询订单详情
- 如果 `executedQty == 0`，提前返回，不执行后续流程

**第二层：持仓更新时的安全检查**
```python
# 防止数量为 0 时导致的除以零错误
if quantity <= 0:
    logger.warning(f"持仓更新跳过: quantity={quantity} <= 0")
    return

# 防止除以零
if new_qty > 0:
    new_cost = (old_qty * old_cost + quantity * price) / new_qty
else:
    logger.error(f"持仓更新异常: new_qty={new_qty} <= 0，跳过更新")
    return
```

**验证结果**：
- ✅ 周末下单：订单提交成功，未成交时不再执行持仓更新
- ✅ 不再出现被 0 除错误
- ✅ 发送未成交通知

**修复文件**：
- `integrations/binance_client.py` - 添加订单详情查询
- `core/trade_executor.py` - 修改下单流程和持仓更新逻辑

## 关键技术细节

### Binance API 签名机制
- 使用 HMAC SHA256 算法
- 参数必须经过 URL 编码（`urlencode`）
- 时间戳误差需小于 5000ms
- 资金账户端点：`/sapi/v1/asset/get-funding-asset`（POST）
- 下单端点：`/sapi/v1/equity/order/place`（POST）
- 订单详情端点：`/sapi/v1/equity/order/detail`（GET）

### 下单响应字段
- `status`: "S"（已接受）或 "F"（失败）
- `orderId`: 订单ID
- `clientOrderId`: 客户端订单ID
- **注意**：这只是请求确认码，不是订单最终状态

### 订单详情响应字段
- `status`: 订单状态（NEW, FILLED, CANCELED 等）
- `executedQty`: 实际成交数量
- `cummulativeQuoteQty`: 实际成交金额
- 这才是订单的真实状态

### 美股交易关键点
- 计价资产：USDC（不是 USD 或 USDT）
- 资金账户：Funding Account（不是 Spot Account）
- 市价买单：传 `notional`（金额）
- 市价卖单：传 `quantity`（股数）
